# Xtrend：整体架构、模块做法与难点

## 0.2.0 的完善

本次保留原分工，设置和星图的共同保存改由已有扩展后台协调；普通设置保存不能开启 Bark。增加本机维护，用于实际删除过期内容与处理用户已启用的排队通知，不刷新 X。

增加自检与安全导出、备份确认恢复、屏蔽原因和临时恢复、读数新鲜度与趋势、按列操作、通知控制、单独目标门槛和批量导出。保存冲突与未保存编辑会明确提示，备份不带设备标识，恢复后监控和 Bark 关闭。

推文淘汰时同步清理速度读数，大内容边读取边限制容量；减少重复页面扫描和不相关界面更新。交付流程检查当前实现的校验值，避免旧报告搭配新安装包。

## 整体如何工作

Xtrend 没有自己的服务器，功能分成四部分：

1. **读取当前页面。**在 X 网页收到内容时，读取一份副本；网页继续照常使用原内容。只识别时间线、推文、转发、引用和所支持的 Grok 请求，不读取私信、聊天历史、账号设置或发帖请求。
2. **在本机整理和计算。**把不同页面提供的数据整理成一致的推文记录，保留作者、正文、日期、数量和图片。平均速度、实测增长、排名与星图均在浏览器内计算。
3. **显示操作面板。**徽章跟随对应推文；浮窗、星图、设置和图片阅读器与 X 原来的界面分开显示。文字、图标与字体都随安装包提供。
4. **只保存必要内容。**设置、规则、色卡、星图缓存与监控命中记录保存在本机；可选 Bark 设备标识也只保存在本地。当前阅读内容、速度读数和回复草稿只放在页面内存中。

主动加载时，界面只能要求“读取这条推文的一页转发或引用”“生成这个提示词的回复”等有限操作，不能要求随意访问网址、发布帖子或改动浏览器资料。页面传来的数据先检查、再显示，正文始终当文字处理。

## 六个模块怎么实现

| 模块 | 做法 | 最需要处理的问题 |
|---|---|---|
| 流速徽章 | 优先使用网页返回的完整数量；按发布时间计算平均值，有新读数时再计算实际增长 | 页面未提供的新浏览量无法推断；缺失数量与真正的零必须区分 |
| 本页热榜 | 只把当前页面已经出现过的推文加入列表；实际增长与平均速度分组；记录跳转前每个滚动区域的位置 | X 会移除屏幕外的旧推文，多列页面还存在多个独立的滚动位置 |
| 图片阅读器 | 依次尝试 X 图片服务的 4096 档、原图和较小版本；缩放围绕鼠标位置，长图改为纵向阅读 | 请求到了图片不代表它实际有 4096 像素；失败时要保留已有图片和阅读位置 |
| Markdown 复制 | 将作者、完整正文、明确日期和原文链接组合，保留段落；正文不完整时加说明 | 长文、引用内容和页面显示的摘录不能混淆；剪贴板可能被浏览器拒绝 |
| 转发星图 | 用原推文连接 X 实际返回的转发者和引用者；人物列表、星图和引用河流共用这些结果 | X 可能只返回一部分人，不能据此声称完整传播路径，也不能编造人与人之间的转发关系 |
| Grok 回复助手 | 先展示将发送的提示词，用户点击后使用当前页面已提供的受支持连接；结果只作为可编辑草稿 | 连接方式、账号权限、限流和临时聊天都由 X 决定，不能用本地不保存来保证 X 也不保存 |

### 热度榜设置

点击热榜上的设置会打开专用窗口，提供显示数量、仅看热帖、四类页面范围、贴边隐藏与六个显示项。有效修改即时显示并自动保存在本机；快速连续操作按顺序保存，不会把前一个修改覆盖掉。至少保留一个显示项，数字为空或不合法时不覆盖已经生效的设置。

“仅看热帖”按浏览量筛选，默认最低 10,000，可修改，同时影响时间线和热榜。筛选只隐藏当前显示内容，不删除推文；未知浏览量保留，收到达到要求的新读数时恢复。关闭过滤或取消当前页面范围，会恢复被隐藏的内容。

贴边隐藏在拖到屏幕左侧或右侧边缘松手时触发；可移入、聚焦或点击边缘标签展开，再拖回中间。取消拖动不会误保存贴边状态。即使当前页面关闭了热榜，也能从工具栏弹窗重新进入设置。

点击热榜标题定位后，会持续标记当前推文与对应条目，并显示连接线。连接线随页面、多列滚动和浮窗位置变化而更新，不会挡住鼠标操作。点击页面空白取消标记；返回、收起热榜、切换页面或原推文被页面移除时，也会清理。选中状态只在当前页面内存中，不写入本地设置。

## 新增的扩展弹窗功能

工具栏弹窗分为过滤、流速榜、监控、外观、AI 评论和关于。通用设置保留在右上角，语言与明暗模式可直接切换。

评论过滤只处理详情页中原推文之后、有明确回复关系的内容，不误把原文或别的页面当评论。白名单优先，再处理黑名单和短语规则。随包提供 26 条规则，三档强度分别启用 1、23、26 条；可单独停用、编辑自定义规则或导入本地文件。没有远程规则下载。

色卡由底色、文字色和强调色组成，可保存、修改和删除，最多 12 张。保存后同时应用到弹窗、热榜、徽章和连接线；过于接近、难以阅读的配色不能保存，深色另行调整。

私有监控只检查浏览时已看到的内容，账号或关键词命中后再核对浏览量和平均速度门槛，不主动请求 X。每个账号下相同推文只自动记录一次，最多保留 200 条、30 天，不留正文。界面可查看、清除或在发送失败后手动重试。

Bark 默认关闭。用户配置并授权服务器后，扩展后台只发送作者、命中原因、数量和链接，不发送正文或 X 登录信息。每分钟最多五次，超出仅本地记录。服务器确认不能替代手机收件确认。Firefox 140 起可单独授权发送网站内容；旧版保持 Bark 停用。本地功能不受影响。

## 为什么不固定星图和 Grok 的访问地址

X 的内部连接方式会变动。Xtrend 从当前标签页已经成功使用过的受支持连接学习，不保留登录资料到文件，也不猜测过期地址。

这带来一个明确限制：首次使用时，可能需要在同一标签页打开一次原生转发／引用列表，或者在 Grok 新建一次纯文字对话。若 X 当前的方式不受支持，会明确说明不可用。仅提供跨站连接时，也不会暗中换到代理或其他 AI 服务。

普通回复生成可能在 X 建立新对话，但不会继续使用原来的私人对话、附带旧历史或附件。临时模式要同时看到受支持的请求标记和 X 返回的确认；否则禁用。

## 浏览器和页面变化如何处理

同一套代码分别生成 Chrome、Edge 和 Firefox 版本。页面识别规则集中维护，X 改动某个部分时，相关模块会显示未知或不可用，而不是用假数据补齐。

页面滚动后若旧推文已消失，无法保证原地重新出现，因此提供原文入口。X Pro 的多列返回会分别恢复各列位置，但真实使用仍需要当前账号拥有访问权限。

安装包不包含本地演示页面。演示页面顶部明确标明使用合成数据，仅用于检查界面和交互。它不能代替真实 X 账号验收；具体已通过与尚未通过的项目见《验证记录》。

需要维护代码时，可进一步阅读英文的 [开发架构说明](ARCHITECTURE.md)。
