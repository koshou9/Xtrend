# Xtrend 0.3.3：架构与维护说明

## 整体分工

保留原有分工：页面读取、内容整理、核心计算、界面和浏览器本机管理。没有新增服务器、统计或远程规则服务。

1. 页面读取层只观察受支持的 X 回应与已显示内容，输出有限字段。
2. 内容工作区校验数据，维护当前页面最多1500条帖子、每条最多60个趋势点；新一批数据只统一排名一次。
3. 核心模块处理数量、排序、过滤、缓存、收藏、导出和监控，界面负责用户输入与结果展示。
4. 扩展后台协调设置、星图、收藏与通知保存，并维护临时 X 原生页面。

## 操作与网页数据分开

网页消息仅用于读取数据和重置页面观察状态。星图加载和 Grok 生成由隔离的扩展界面直接交给后台；网页不能通过消息要求打开页面或提交提示词。原有页面中学习连接后重放请求的操作路径已删除，避免绕过用户按钮，也减少两套方式同时维护。

临时页面中的 X 自己处理当前连接。星图支持一页一页读取，Grok 只在点击生成后提交提示词，不复用私人历史。临时聊天尚未确认，保持不可用。取消、切换页面或账号、关闭原页面和过期都会清理任务。图像、星图和草稿的访问仍取决于 X 的可用性。

## 数据保存

- 设置：最多750KB；普通保存不能启用 Bark 或改变其目的地。
- 星图：按账号分开，7天过期，总预算5MB；匿名时不长期保存。
- 监控：30天、最多200条，预算1MB，不保存正文。
- 收藏：用户明确点击保存，最多100条／2MB，包含选中正文、标签和备注，本机跨账号共享。超限明确拒绝，不自动删除旧收藏；设置备份不包含收藏。
- 通知控制数据：保留有限次数与时间，测试、重试和自动发送共用限制。
- 草稿、当前页面读数、筛选与批量选择留在页面内存。

## 功能边界

热榜和搜索只处理本页已经读到的帖子。监控不主动轮询 X；再次提醒需要至少5分钟后的新准确读数，且比上次命中增长所选比例。安静时段、发送间隔、次数限制、关闭后不补发等规则继续生效。

Pro 列在当前页面使用不会重复的身份；列的显示顺序可能变化，设置按当前选择的身份应用。刷新或 X 重建全部列后需要核对单列设置，真实 Pro 仍需有权限的账号验收。

## 维护与验证

优先修复已复现的问题，不整体重写。共享规则在核心层维护，界面沿用现有控件与三种语言。浏览器交互检查使用隔离构造页面，不访问真实账号。交付流程检查代码、功能、三种构建、浏览器操作、依赖安全、Firefox载入与提示，并将结果与当时源码对应。

详细优先级和验收见[优化说明](OPTIMIZATION-0.3.0.md)，当前验证边界见[验证记录](VERIFICATION.md)。
